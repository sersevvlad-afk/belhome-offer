BELHOME LINK STUDIO — КАК ЗАПУСТИТЬ БЕСПЛАТНО

ЧТО ВНУТРИ
1) index.html — страница, которую открывает клиент.
2) studio.html — кабинет менеджера для создания персональной ссылки.
3) assets/ — общие изображения и планировки.
4) .nojekyll — служебный файл для GitHub Pages.

КАК ПРОВЕРИТЬ НА КОМПЬЮТЕРЕ
- Откройте studio.html.
- Измените имя, цену, проект и расчёт.
- Нажмите «Открыть как клиент».
- Локально картинка/планировка должны лежать в папке assets рядом с файлами сайта.

КАК ОПУБЛИКОВАТЬ НА GITHUB PAGES БЕСПЛАТНО
1) Создайте бесплатный аккаунт GitHub, если его нет.
2) Создайте PUBLIC repository, например: belhome-offer.
3) Загрузите в корень репозитория всё содержимое этой папки: index.html, studio.html, .nojekyll и папку assets.
4) Repository → Settings → Pages.
5) Build and deployment → Source → Deploy from a branch.
6) Branch: main, Folder: /(root), Save.
7) После публикации GitHub покажет адрес сайта вида:
   https://USERNAME.github.io/belhome-offer/
8) Откройте:
   https://USERNAME.github.io/belhome-offer/studio.html
9) Кабинет автоматически будет генерировать ссылки вида:
   https://USERNAME.github.io/belhome-offer/index.html#o=...

КАК ДОБАВИТЬ НОВУЮ ПЛАНИРОВКУ
- В GitHub откройте папку assets.
- Add file → Upload files.
- Загрузите, например, plan-96.png.
- В кабинете в поле «Планировка» укажите:
  assets/plan-96.png
- После этого этот путь можно использовать в любом количестве КП.

ПОЧЕМУ ТАК
- Цена, имя, скидка, срок, расчёт и контакты зашиваются в персональную ссылку.
- Изображения не зашиваются в ссылку, чтобы она не стала огромной.
- Один сайт публикуется один раз. Для каждого нового клиента ничего заново на GitHub публиковать не нужно, если используются уже загруженные проекты/планировки.

ВАЖНО
- Ссылка сама по себе содержит данные КП. Не включайте в неё чувствительные персональные данные, паспортные данные и т.п.
- GitHub Pages — публичный статический хостинг. Для коммерческого КП здесь лучше хранить только обычные продающие материалы, планировки, цены и контакт менеджера.
- Аналитика открытий в этой версии отсутствует: для неё нужен внешний сервис/сервер или отдельная аналитическая интеграция.


НОВАЯ ВЕРСИЯ: АВТОЗАГРУЗКА ИЗОБРАЖЕНИЙ В GITHUB
- Откройте studio.html на опубликованном GitHub Pages.
- Укажите GitHub owner, repository и branch (обычно main).
- Создайте fine-grained Personal Access Token только для репозитория сайта.
- Разрешение токена: Repository permissions → Contents → Read and write.
- Вставьте токен в studio.html. Он хранится только в sessionStorage текущей вкладки и в клиентскую ссылку не попадает.
- Нажмите «Проверить GitHub».
- После этого возле каждого изображения нажимайте «Загрузить изображение».
- Файл автоматически попадёт в assets/, а путь автоматически подставится в КП.
- GitHub Pages может обновлять файл не мгновенно; обычно нужно немного подождать перед проверкой клиентской ссылки.

БЕЗОПАСНОСТЬ
- Используйте Fine-grained token, ограниченный только одним репозиторием.
- Не давайте токену Administration/Workflows и другие лишние права.
- Не отправляйте токен клиенту и не вставляйте его в КП.
